\subsection{Floating Point Arithmetic}
\label{sub:floating-point}

\textBox{%
Digital computers store only finitely many real numbers. Even when a formula is exact on paper, its implementation rounds intermediate results to this finite set. We need to determine the size of one rounding error before studying how an algorithm propagates many of them.
}

\textBox{%
Floating-point arithmetic is usually accurate locally, since one elementary operation is rounded to a nearby representable number. Instability appears when an algorithm repeatedly amplifies these tiny local errors, or when it subtracts nearly equal quantities and exposes digits that were already contaminated by rounding.
}

\subsubsection{Floating Point Representation}

In binary floating-point arithmetic, a normalized number is stored in the form $x=(-1)^s(1.f)_2\,2^e$. The subscript $2$ means that the digits after the point represent powers $2^{-1},2^{-2},\ldots$. IEEE 754 specifies common formats and rounding rules. The fields have the following roles.
\begin{itemize}
  \item \textbf{s:} Sign bit, determining whether the number is positive or negative.
  \item \textbf{f:} Fractional significand (mantissa). The leading 1 is implicit to maximize precision.
  \item \textbf{e:} Unbiased exponent. The stored exponent field adds a fixed bias to $e$; reserved fields encode zeros, subnormals, infinities, and NaNs.
\end{itemize}

\textBox{%
The exponent controls scale and the significand controls precision. This means floating-point numbers have roughly fixed \textbf{relative} spacing, not fixed absolute spacing. There are many representable numbers near zero and far fewer, in absolute terms, near $10^{100}$. The gap between adjacent numbers near $x$ is proportional to $|x|$.
}

\addRemark{%
\textbf{(IEEE 754 Standards)}\enspace
\begin{itemize}
  \item \textbf{Single (32-bit):} 1 sign, 8 exponent, 23 fraction bits.
  \item \textbf{Double (64-bit):} 1 sign, 11 exponent, 52 fraction bits.
\end{itemize}
}

\addExmpl{%
A binary16 number has one sign bit, five exponent bits, and ten fraction bits. The exponent bias is $15$. To store $-3.25$, we compute the fields as follows.
\begin{enumerate}
  \item $s=1$.
  \item $3.25_{10} = 11.01_2 = 1.101_2 \times 2^1$.
  \item $e = 1+15 = 16 = 10000_2$.
  \item $f = 1010000000_2$.
\end{enumerate}
Result: \texttt{1 10000 1010000000}.
}

\addExcr{%
\begin{enumerate}
  \item Encode $+5.5$ in 16-bit format.
  \item How many distinct normalized numbers for 5 exp bits, 10 frac bits?
\end{enumerate}
}

\addDef{Machine Epsilon ($\varepsilon_{\text{mach}}$)}{%
Machine epsilon is the distance from $1$ to the next larger floating-point number. It is a spacing, rather than the threshold at which an increment first changes a rounded sum. It characterizes the spacing of representable numbers near $1$ and is given by $\varepsilon_{\text{mach}} = 2^{1-p}$, where $p$ is the number of bits in the significand.
\begin{itemize}
  \item For double precision (64-bit), $\varepsilon_{\text{mach}} \approx 2.22 \times 10^{-16}$.
\end{itemize}
}
\label{def:mach-eps}

\addRemark{%
\textbf{(Spacing rule)}\enspace Near a normalized number $x$, the distance to the next representable number is approximately $\varepsilon_{\text{mach}}|x|$. Near $10^{16}$, the gap is on the order of $1$, whereas near $1$, the gap is on the order of $10^{-16}$. This explains why adding a small number to a sufficiently large number has no effect.
}

\addThm{Absorption Criterion}{%
Let $x$ be a representable number with two finite neighbors. In round-to-nearest arithmetic, if $|y|$ is less than half the smaller of the two distances from $x$ to its neighbors, then
\begin{align*}
    \operatorname{fl}(x+y)=x.
\end{align*}
Equivalently, small increments disappear when they are below the local resolution of the floating-point grid.
}
\label{thm:absorption-criterion}

\addExcr{%
\begin{enumerate}
  \item Use Def~\ref{def:mach-eps} to predict whether \texttt{1.0 + 1e-16} and \texttt{1.0 + 2e-16} differ from \texttt{1.0}. Then test the prediction in Python.
  \item Find $\varepsilon_{\text{mach}}$ empirically via loop.
  \item Use Thm~\ref{thm:absorption-criterion} to predict the smallest power of $10$ for which \texttt{1e16 + 10**k} changes \texttt{1e16}.
  \item Explain why the answer changes if \texttt{1e16} is replaced by \texttt{1.0}.
\end{enumerate}
}
\label{ex:spacing-absorption}

\addDef{Unit Roundoff ($u$)}{%
Unit roundoff bounds the relative error caused by rounding a nonzero real number within the normalized range to the nearest floating-point number:
\begin{align*}
  \frac{|\text{fl}(x) - x|}{|x|} \leq u.
\end{align*}
For round-to-nearest arithmetic, $u = \varepsilon_{\text{mach}}/2 = 2^{-p}$.
}
\label{def:unit-roundoff}

\addRemark{%
\textbf{(Machine epsilon vs.\ unit roundoff)}\enspace $\varepsilon_{\text{mach}}$ is a spacing near $1$. The unit roundoff $u$ is an error bound for rounding to nearest. Many texts use ``machine epsilon'' for both quantities, so always check the convention. In these notes, elementary rounding errors are bounded by $u$.
}

\addThm{Fundamental Axiom}{%
Suppose the exact result $a\circ b$ is finite, nonzero, and lies in the normalized floating-point range. In round-to-nearest arithmetic,
\begin{align*}
    \operatorname{fl}(a\circ b)=(a\circ b)(1+\delta),
    \qquad |\delta|\leq u,
\end{align*}
for $\circ\in\{+,-,\times,\div\}$. Overflow and gradual underflow require separate absolute-error models.
}
\label{thm:fp-axiom}

\addPrf{%
Assume rounding to nearest, and exclude overflow and the subnormal range as in the theorem. It suffices to consider $|x|$, because the representable numbers and rounding rule are symmetric about zero.
\begin{enumerate}
\item Choose the integer $e$ such that $2^e\leq|x|<2^{e+1}$. In this interval, changing the last stored significand bit changes the value by $s=2^{e+1-p}$. Thus consecutive representable normalized values are separated by $s$.
\item Rounding to nearest selects one of the two representable values surrounding $|x|$. Its distance is at most half their separation. Therefore
\begin{align*}
 |\operatorname{fl}(x)-x|\leq\frac{s}{2}=2^{e-p}.
\end{align*}
At an exactly representable value the error is zero, which also satisfies this bound.
\item Since $|x|\geq2^e>0$,
\begin{align*}
 \frac{|\operatorname{fl}(x)-x|}{|x|}
 \leq\frac{2^{e-p}}{2^e}=2^{-p}=u.
\end{align*}
Define $\delta=(\operatorname{fl}(x)-x)/x$. Then $\operatorname{fl}(x)=x(1+\delta)$ and $|\delta|\leq u$. For $x=0$, take $\delta=0$.
\end{enumerate}
}

\addRemark{%
\textbf{(Accumulation of rounding errors)}\enspace A sequence of $n$ benign operations often produces an error proportional to $nu$ when $nu\ll1$. The rule is a heuristic. Cancellation and ill-conditioning can amplify the perturbations well beyond $nu$. Operation order matters because every intermediate result is rounded.
}

\addExcr{%
Let $x=1$ and $y=1-10^{-12}$ be exact real data, and let $\hat x$ and $\hat y$ be their rounded values. Distinguish the error made when subtracting $\hat x-\hat y$ from the error caused by rounding $x$ and $y$ before subtraction. Which error does the fundamental rounding model bound? Estimate the amplification of the operand errors relative to $x-y$.
}

\subsubsection{IEEE 754 Special Values}

\textBox{%
\begin{itemize}
  \item \textbf{Signed Zero:} $+0, -0$. $1/(+0) = \infty$, $1/(-0) = -\infty$.
  \item \textbf{Subnormals:} Fill the gap between 0 and the smallest normalized number. Reduced precision, allows gradual underflow.
  \item \textbf{Infinities:} $\pm\infty$. Result of overflow or $x/0$.
  \item \textbf{NaN:} Not a Number ($0/0$, $\infty-\infty$). Unequal to everything, including itself.
\end{itemize}
}

\addRemark{%
\textbf{(NaN propagation)}\enspace A NaN usually contaminates all later arithmetic. This behavior helps with debugging, because the NaN marks an invalid operation that happened earlier even if the failure is observed much later.
}

\addExcr{%
\begin{enumerate}
  \item Using NumPy scalars, compare \texttt{np.float64(1.0)/np.float64(0.0)} with division by \texttt{np.float64(-0.0)}. Explain the warnings and the signs of the results. (Python's built-in float division raises \texttt{ZeroDivisionError} instead.)
  \item Evaluate \texttt{float('inf') - float('inf')} and \texttt{float('nan') == float('nan')}.
\end{enumerate}
}

\subsubsection{Arithmetic Pitfalls}

\textBox{%
Because floating-point numbers are discrete, the standard laws of algebra do not always hold. In particular, operations are neither associative nor distributive in general.
}
\begin{itemize}
  \item \textbf{Non-Associativity:} The order of operations can change the result, i.e., $(a+b)+c \neq a+(b+c)$.
  \item \textbf{Non-Distributivity:} $a(b+c) \neq ab + ac$.
  \item \textbf{Absorption:} If $|a|$ is much larger than $|b|$, then $a+b$ may equal $a$ exactly because $b$ is smaller than the gap between representable numbers near $a$.
\end{itemize}

\addExmpl{%
\textbf{(Absorption)}\enspace In double precision, \texttt{1e16 + 1.0 == 1e16} is true. The number $1$ is smaller than the spacing between adjacent representable numbers near $10^{16}$, so it is rounded away. Consequently \texttt{(1e16 + 1.0) - 1e16} returns \texttt{0.0}, not \texttt{1.0}.
}

\addExmpl{%
\textbf{(Non-associativity)}\enspace Let $a=10^{16}$, $b=-10^{16}$, and $c=1$. Then
\begin{align*}
    (a+b)+c = 1, \qquad a+(b+c) = 0
\end{align*}
in double precision. The second expression first rounds $b+c$ back to $-10^{16}$, so the $1$ is lost before the final addition.
}

\addRemark{%
\textbf{(Summation rule)}\enspace Add numbers of similar magnitude when possible. Summing from smallest to largest, pairwise summation, or compensated summation reduces the loss of small terms. Consequently, library reductions may give different answers than a hand-written loop and still be more accurate.
}

\addExcr{%
\begin{enumerate}
  \item Before running Python, use Thm~\ref{thm:absorption-criterion} to predict \texttt{(1e16 + 1.0) - 1e16}.
  \item \texttt{a=1e16, b=1}. Find \texttt{(a+b)-a} in Python. Explain result.
  \item Find $a, b, c$ where \texttt{a*(b+c) != a*b + a*c}.
  \item Before running Python, predict the results of summing $[10^{16}, 1, -10^{16}]$ in the listed order and in the order $[10^{16}, -10^{16}, 1]$.
  \item Compare naive summation, pairwise summation, and Kahan summation on a list containing one large number and many small numbers. Which method best preserves the small terms?
\end{enumerate}
}
\label{ex:floating-point-prediction}

\subsection{Quantifying Approximation Error}
\label{sub:error-analysis}

\subsubsection{Absolute and Relative Errors}

\textBox{%
\begin{itemize}
  \item \textbf{Absolute Error:} $|\hat{x} - x|$.
  \item \textbf{Relative Error:} $\varepsilon = \frac{|\hat{x} - x|}{|x|}$. This is the standard measure for precision in numerical computing.
\end{itemize}
}

\textBox{%
Absolute error measures the size of the mistake in the original units. Relative error measures the size of the mistake compared to the quantity being computed. In numerical computing, relative error is usually more informative. An error of $10^{-6}$ is excellent for a number of size $10^3$ and terrible for a number of size $10^{-9}$.
}

\addRemark{%
\textbf{(Comparing floating-point numbers)}\enspace Avoid testing computed real numbers with exact equality. Use a tolerance such as
\begin{align*}
    |\hat{x}-x| \leq \text{atol} + \text{rtol}|x|.
\end{align*}
This principle underlies \texttt{np.isclose}. The absolute tolerance bounds errors near zero, whereas the relative tolerance scales with magnitude.
}

\addExcr{%
\begin{enumerate}
  \item Compute the absolute and relative errors of using $1.414$ for $\sqrt2$.
  \item Let $\hat x=x(1+\delta_x)$ and $\hat y=y(1+\delta_y)$ with $xy\neq0$. Derive the exact relative perturbation of $\hat x\hat y$ before rounding the product. Bound it when $|\delta_x|,|\delta_y|\leq u$, and identify the first-order term.
\end{enumerate}
}

\addDef{Catastrophic Cancellation}{%
\textbf{Catastrophic cancellation} occurs when two nearly equal approximations are subtracted. The leading digits cancel, so errors already present in the operands become large relative to the small difference.
\begin{itemize}
  \item For $x\neq y$ and operand errors $|\hat x-x|\leq u|x|$, $|\hat y-y|\leq u|y|$, exact subtraction of the perturbed operands has relative error at most $u(|x|+|y|)/|x-y|$. Rounding that subtraction contributes a further local error.
  \item As $x \to y$, the amplification factor $(|x|+|y|)/|x-y|$ can become arbitrarily large.
\end{itemize}
}
\label{def:cancellation}

\addPrf{%
We distinguish errors in the operands from any additional rounding of the subtraction itself. Assume $x-y\neq0$, since relative error with respect to a zero answer is undefined. Write the perturbed operands as
\begin{align*}
 \hat x=x(1+\varepsilon_x),\qquad
 \hat y=y(1+\varepsilon_y),\qquad
 |\varepsilon_x|,|\varepsilon_y|\leq u.
\end{align*}
First regard $\hat x-\hat y$ as an exact real subtraction of these perturbed data. Expand and cancel the unperturbed terms:
\begin{align*}
 (\hat x-\hat y)-(x-y)
 &=x+x\varepsilon_x-y-y\varepsilon_y-x+y\\
 &=x\varepsilon_x-y\varepsilon_y.
\end{align*}
The triangle inequality and the operand bounds give
\begin{align*}
 |(\hat x-\hat y)-(x-y)|
 &\leq |x||\varepsilon_x|+|y||\varepsilon_y|\\
 &\leq u(|x|+|y|).
\end{align*}
Dividing by $|x-y|>0$ yields the stated amplification factor.

This factor can be large when the operands have comparable nonzero magnitude but their difference is small. It measures sensitivity to the operand errors. If the subtraction is also rounded, the floating-point model adds a further error bounded by $u|\hat x-\hat y|$ in absolute value. That additional operation error is separate from the potentially amplified operand errors. The bound does not assert that every subtraction exhibits its worst possible error.
}

\addRemark{%
\textbf{(Numerical stability principle)}\enspace Rounding error is an inevitable consequence of finite precision. However, catastrophic cancellation is an algorithmic flaw that can often be avoided by mathematically rearranging the problem.
}

\addExmpl{%
\textbf{(Stabilizing Cancellation)}\enspace $f(x) = \sqrt{x+1} - \sqrt{x}$ for $x = 10^{16}$.
\begin{itemize}
  \item \textbf{Direct:} In double precision, both square roots round to $10^8$, so the computed difference is zero.
  \item \textbf{Stable:} $\frac{1}{\sqrt{x+1} + \sqrt{x}} \approx 5 \times 10^{-9}$.
\end{itemize}
}

\addExmpl{%
\textbf{(Quadratic formula)}\enspace The roots of $ax^2+bx+c=0$ are
\begin{align*}
    x_{\pm} = \frac{-b \pm \sqrt{b^2-4ac}}{2a}.
\end{align*}
If $b^2 \gg 4ac$, one numerator subtracts nearly equal numbers. A stable strategy computes the root with no cancellation first, then uses $x_1x_2=c/a$ to recover the other root.
}

\addRemark{%
\textbf{(Use stable library functions)}\enspace Functions such as \texttt{log1p(x)}, \texttt{expm1(x)}, and \texttt{hypot(x, y)} implement stable rearrangements for common cancellation and overflow patterns. Prefer them over hand-expanded formulas when the inputs may be small, large, or nearly cancelling.
}

\addExcr{%
Stabilize:
\begin{enumerate}
  \item Use Def~\ref{def:cancellation} to explain why $(1-\cos x)/x^2$ is unstable for small $x$, then derive a stable form.
  \item Use Def~\ref{def:cancellation} to identify which root of $x^2 - 10^8 x + 1 = 0$ is unstable in the quadratic formula, then compute it using $x_1x_2=c/a$.
  \item Use the Taylor series of $e^x$ to explain why $e^x - 1$ loses relative accuracy for small $x$. Compare with \texttt{np.expm1}.
\end{enumerate}
}
\label{ex:cancellation-stabilization}

\subsubsection{Error Analysis}

\textBox{%
A computed result can be judged in two ways. Forward error analysis bounds the distance between the computed output and the exact output. Backward error analysis instead seeks the smallest perturbation of the input for which the computed output is exact. An algorithm is \textbf{backward stable} if this perturbation is a modest multiple of the unit roundoff $u$ for every input.
}

\textBox{%
Backward error is often easier to bound than forward error, and it is directly comparable with the uncertainty in the data. If the input is known only to a relative accuracy larger than the backward error, the algorithm has introduced no error beyond what the data already contain. The condition number then converts a backward error into a forward error.
}

\addDef{Condition Number ($\kappa$)}{%
The condition number measures the local sensitivity of a problem's output to perturbations in its input. For sufficiently small relative perturbations, the first-order relation has the form
\begin{align*}
    \text{relative forward error}
    \lesssim \kappa\,\text{relative backward error},
\end{align*}
with the precise definition of $\kappa$ determined by the problem and the chosen norms. For the linear system $\bA\bx=\bb$, Section~\ref{sub:stability-theory} shows that this role is played by the matrix condition number of Def~\ref{def:condition-number-geometric}.
}
\label{def:cond-num-intro}

\addRemark{%
\textbf{(Stability vs.\ conditioning)}\enspace Conditioning is a property of the mathematical problem. Stability is a property of the algorithm. A stable algorithm can still return a poor answer on an ill-conditioned problem, because the problem itself amplifies small perturbations.
}

\addExcr{%
A problem has condition number $\kappa=10^8$, and an algorithm computes a solution with relative backward error $10^{-15}$. Use Def~\ref{def:cond-num-intro} to estimate the largest relative forward error, and state how many correct significant digits the result can be expected to have.
}
